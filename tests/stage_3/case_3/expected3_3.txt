Повреждённые файлы (обрезанные, битые)

ВХОДНЫЕ ДАННЫЕ:

- broken.docx — обрезанный DOCX (например, копия РПД_языки программирования.docx,
                обрезанная на 50%)
- broken.xlsx — обрезанный XLSX (например, копия UP_short.xlsx,
                обрезанная на 50%)

ОЖИДАЕМОЕ ПОВЕДЕНИЕ:

1. При загрузке broken.docx:
   - Файл принимается (расширение корректное)
   - Создаётся задача обработки
   - Статус: pending → processing → failed
   - Ошибка: "файл повреждён" или "не удалось прочитать DOCX"

2. При загрузке broken.xlsx:
   - Файл принимается (расширение корректное)
   - Создаётся задача обработки
   - Статус: pending → processing → failed
   - Ошибка: "файл повреждён" или "не удалось прочитать XLSX"

ОЖИДАЕМЫЙ РЕЗУЛЬТАТ:
Система не падает ни на одном файле.
Каждый битый файл даёт понятную ошибку.

ЧТО ПРОВЕРЯЕМ КОНКРЕТНО:

1. Повреждённые файлы:
   - Система не падает
   - Статус: failed
   - Ошибка понятная: "файл повреждён" / "не удалось прочитать"
   - Задача обработки создана (расширение-то валидное)

2. Сообщения об ошибках:
   - Конкретные: "не удалось прочитать DOCX", "не удалось прочитать XLSX"
   - Понятны пользователю
   - Видны в интерфейсе, а не только в логах

3. Поведение системы:
   - Не создаёт "пустую программу" без предупреждения
   - Не сохраняет битые данные как валидные
   - Не падает на обрезанных файлах

4. Различие с пустыми файлами (кейс 3.2):
   - Пустой файл 0 байт → ошибка "файл пуст"
   - Обрезанный файл → ошибка "файл повреждён"
   - Это РАЗНЫЕ ошибки. Пользователь должен видеть разницу.

ЧЕГО НЕ ДОЛЖНО БЫТЬ:
- Падения системы на любом из файлов
- Статуса completed
- Молчаливого пропуска (файл "обработан", но данных нет, и никто не заметил)
- Создания "пустой программы" в хранилище без пометки об ошибке
- Общей ошибки "не удалось обработать" без указания причины
- Ошибки, которую видно только в логах
