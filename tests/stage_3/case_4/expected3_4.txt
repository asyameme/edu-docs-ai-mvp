Повторная загрузка того же файла (дубликат)

ВХОДНЫЕ ДАННЫЕ:
- UP_short.xlsx — учебный план (загружается дважды)

СЦЕНАРИЙ:
1. Загрузка UP_short.xlsx (первый раз).
2. Обработка завершается успешно (статус completed).
3. Загрузка UP_short.xlsx (второй раз, тот же файл, тот же размер, то же содержимое).
4. Наблюдаем за поведением системы.

ОЖИДАЕМОЕ ПОВЕДЕНИЕ (один из трёх вариантов — требует согласования):

ВАРИАНТ A (обновление существующей версии):
1. Система распознаёт дубль по хешу файла.
2. Система предлагает пользователю:
   "Этот файл уже загружен. Обновить существующую программу?"
3. Если пользователь подтверждает:
   - Существующая версия обновляется
   - Новая версия НЕ создаётся
4. Если пользователь отказывается:
   - Загрузка отменяется
   - Ничего не меняется

ВАРИАНТ B (создание новой версии):
1. Система распознаёт, что файл уже был загружен.
2. Система создаёт новую версию программы (v3).
3. История сохраняется: v1, v2, v3.
4. Пользователь может переключаться между версиями.
5. В интерфейсе видно, что v3 основана на том же файле, что v1.

ВАРИАНТ C (отклонение дубля):
1. Система распознаёт, что файл уже был загружен.
2. Система отклоняет загрузку с ошибкой:
   "Этот файл уже загружен. Дубликаты не поддерживаются."
3. Новая версия не создаётся.
4. Существующая версия не меняется.

ОЖИДАЕМЫЙ РЕЗУЛЬТАТ:
Система не создаёт дублей сущностей молча. Поведение предсказуемо и понятно пользователю.

ЧТО ПРОВЕРЯЕМ КОНКРЕТНО:

1. Распознавание дубля:
   - Система понимает, что файл уже был загружен
   - Определяет это по хешу содержимого, а не по имени файла
   - (Если два разных файла с одинаковым именем — это НЕ дубль)

2. Поведение при повторной загрузке:
   - Согласно выбранному варианту (A, B или C)

3. Состояние хранилища после повторной загрузки:
   - Нет дублей сущностей (две одинаковые программы)
   - Нет потери первой версии
   - История версий корректна

4. Сообщения пользователю:
   - Понятные: "файл уже загружен" / "создана новая версия" / "обновить?"
   - Не общие ("ошибка")

ЧЕГО НЕ ДОЛЖНО БЫТЬ:
- Молчаливого создания дублей сущностей (две программы из одного файла)
- Потери первой версии
- Падения системы
- Обработки файла дважды без предупреждения
- Ошибки без указания причины
- Создания "фантомной" версии без реальных данных

ОСОБЫЕ СЛУЧАИ:
- Что если файл загружен, но обработка ещё не завершена (статус processing)?
  Система должна либо дождаться, либо сказать "файл уже в обработке".
- Что если файл загружен с другим именем, но тем же содержимым?
  Это всё равно дубль — система должна распознать по хешу.
- Что если файл загружен с тем же именем, но другим содержимым?
  Это НЕ дубль — это другая версия. Система должна создать новую версию.
- Что если пользователь удалил первую версию и загружает файл снова?
  Это уже не дубль — можно создать новую программу.

ВАЖНЫЙ НЮАНС:
Ключевой критерий дубля — ХЕШ СОДЕРЖИМОГО, а не имя файла.
Если система определяет дубль по имени — это неправильно:
  - Два разных файла с одинаковым именем не дубли
  - Один и тот же файл с разными именами — дубль

ВОПРОС КОМАНДЕ:
"Какой вариант выбираем: A, B или C?"
Это архитектурное решение, от него зависит:
  - Логика backend (хеширование, проверка дублей)
  - UI (подтверждение обновления или нет)
  - Поведение хранилища (версии или перезапись)
