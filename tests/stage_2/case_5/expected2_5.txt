Сохранение конфликта и решения пользователя

ВХОДНЫЕ ДАННЫЕ:
- UP_short.xlsx                              — учебный план
- С1_001856_Математический анализ I.docx     — РПД с испорченной таблицей

Известные конфликты (из кейса 1.1):
- Конфликт 1 (внутренний): сумма часов 206 ≠ 3 з.е. (108 ч)
- Конфликт 2 (внутренний): шапка РПД 6 з.е. ≠ таблица 3 з.е.
- Конфликт 3 (внешний): УП 6 з.е. (216 ч) vs РПД 3 з.е. (206 ч)

СЦЕНАРИЙ:
1. Загрузка обоих документов.
2. Система находит 3 конфликта.
3. Все 3 конфликта сохраняются в хранилище.
4. Каждому конфликту присваивается:
   - ID
   - тип: "внутреннее несоответствие часов" / "расхождение з.е." / "расхождение часов"
   - статус: "открыт"
   - ссылки на конфликтующие сущности
   - оба значения
5. Пользователь разрешает конфликты:
   - Конфликт 1: выбирает 206 часов (по разбивке)
   - Конфликт 2: выбирает 6 з.е. (значение из шапки)
   - Конфликт 3: выбирает 6 з.е. из УП
6. Решения сохраняются в хранилище:
   - ID решения
   - ссылка на конфликт
   - выбранное значение
7. Статус каждого конфликта: "открыт" → "закрыт".
8. При чтении конфликтов по ID возвращаются:
   - конфликт
   - решение
   - статус "закрыт"

ОЖИДАЕМЫЙ РЕЗУЛЬТАТ:
Все 3 конфликта сохранены, все 3 решения сохранены, статусы обновлены,
связи корректны.

ЧТО ПРОВЕРЯЕМ КОНКРЕТНО:

1. Сущности «Конфликт»:
   - 3 отдельных записи с уникальными ID
   - Типы сохранены: внутреннее несоответствие / расхождение з.е. /
     расхождение часов
   - Оба значения каждого конфликта сохранены
   - Ссылки на конфликтующие сущности корректны
   - Статус изначально "открыт" у всех трёх

2. Сущности «Решение»:
   - 3 отдельных записи с уникальными ID
   - Каждая привязана к своему конфликту
   - Хранят выбранные значения
   - Не могут существовать без конфликта

3. Связи «Конфликт ↔ Решение»:
   - Каждый конфликт имеет ровно одно решение
   - Связи не теряются при чтении
   - Нет дублей связей

4. Статусы конфликтов:
   - До решения: "открыт"
   - После решения: "закрыт"
   - Все три статуса обновлены

5. Повторное чтение:
   - Каждый конфликт по ID возвращает и решение, и статус
   - Нет дублей конфликтов
   - Нет дублей решений

ЧЕГО НЕ ДОЛЖНО БЫТЬ:
- Потери хотя бы одного из 3 конфликтов
- Потери хотя бы одного из 3 решений
- Сироты-решения (решение без конфликта)
- Дублей конфликтов (один и тот же конфликт дважды)
- Дублей решений
- Потери значений конфликтов
- Статуса "открыт" после сохранения решения
- Конфликта без ссылки на дисциплину
- «Схлопывания» трёх конфликтов в один
- Привязки одного решения к нескольким конфликтам
