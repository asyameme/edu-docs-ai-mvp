# Хранилище второго этапа и предварительная предметная модель

Дата: 2026-10-10. Реализованы четыре таблицы в education:

| Таблица | Постоянные данные |
|---|---|
| programs | UUID, название, текущая версия, время создания |
| program_versions | UUID, номер, родитель, снимок JSONB, origin, restored_from, ключ/хэш операции |
| source_documents | UUID, программа, имя, формат, размер, SHA-256, внутренний ключ файла |
| version_documents | Документы конкретной версии; производная связь из document_ids |

Создание программы и пустой V1 атомарно. Каждая запись создаёт полный снимок.
Восстановление создаёт новую версию, родитель — текущая, restored_from — выбранная старая.
UUID сущности сохраняет клиент при изменении её кода. Сервер не сопоставляет сущности по смыслу.

## Снимок schema_version=1

- metadata: произвольные метаданные программы.
- entities: id UUID, kind, attributes JSON, source_ref_ids.
- kind: discipline, semester_load, competency, indicator, learning_outcome,
  control_form, assessment_tool.
- relations: id UUID, source_id, target_id, type, source_ref_ids,
  confidence (null либо число 0–1).
- source_refs: id UUID, document_id, section (необязательный), locator (непустой указатель).
- document_ids: UUID оригиналов этой версии.

Списки по умолчанию пустые; null сохраняется без замены на ноль. Числа должны быть конечными.
Неизвестные предметные атрибуты допускаются в attributes; обязательность уточняется с командой.
Повторяющиеся ID, отсутствующие концы связей/источники, чужие документы отклоняются до записи.
Все источники ссылаются на документы своей программы, включённые в document_ids.

Транзакция блокирует строку программы FOR UPDATE, проверяет повтор ключа, затем ожидаемую
версию, добавляет снимок/связи документов и меняет текущий указатель. При ошибке всё откатывается.
Уникальные ограничения защищают номер и ключ в рамках программы. Составные внешние ключи
не допускают межпрограммных связей. Триггеры запрещают UPDATE/DELETE снимков и оригинальных
метаданных. JSONB не является заменой валидации: структура проверяется приложением.

Alembic 0001_program_storage создаёт эту схему, использует блокировку миграций и допускает
только education. Приложение продолжает использовать psycopg, без перехода на ORM.
Шаблон миграции: migrations/script.py.mako. Базы Temporal не изменяются Alembic.

## Как хранить и объяснять факты

1. PostgreSQL хранит факты, версии, ссылки на исходники и решения. Chroma хранит индекс
   с program_id/version_id/source_ref_id, чтобы не смешивать программы и версии.
2. Исходные файлы не перезаписываются правками. Файл хранится отдельно, база — его метаданные.
3. Код компетенции изменяемый; внутренний ID не меняется вместе с кодом.
4. Каждая связь принадлежит конкретной версии. Дисциплина может формировать несколько
   компетенций, и компетенция может быть связана с несколькими дисциплинами.
5. Часы не сводятся к одному числу без проверки: дисциплина может идти в нескольких
   семестрах. Состав разбивки определяется по документам команды.
6. Противоречие не устраняется выбором первого встреченного значения. Оба наблюдения
   сохраняются с источниками. В демонстрации hours=null до решения конфликта 108/144.
7. Статус confirmed фиксирует выбор версии человеком, но не доказывает нормативное соответствие.
8. Уверенность ML — дополнительная оценка, а не сохранённый доказанный факт.

## Указатели источников

- XLSX: лист и ячейка/диапазон, например sheet:План!D12.
- DOCX: раздел и порядковый блок/таблица/строка/ячейка. Номер страницы без рендеринга ненадёжен.
- PDF: номер страницы и расположение фрагмента; OCR рассматривается отдельно позднее.

## Пример

Учебный план утверждает 108 часов, РПД — 144. Создаются два Observation с разными SourceRef,
один Conflict для hours одной дисциплины. Пока решение не принято, выбранное значение отсутствует.
Будущая правка создаёт новую версию; старый вариант остаётся доступным для просмотра.

## Что проверить на документах

Коды дисциплин, единицы часов/зачётных единиц, распределение по семестрам, типы компетенций,
контроль, результаты обучения, связь оценочных средств с индикаторами, правила выбора варианта.
Не вводить неизвестные обязательные поля до получения примеров.
