# Граница Backend / ML — предварительный обмен

Технический парсер, смысловое извлечение и логика агента принадлежат ML-команде,
согласно распределению ответственности в roadmap.
Бэкенд хранит оригиналы, запускает обработку, передаёт прогресс и сохраняет результаты.
Форматы обмена ниже предварительные и требуют согласования с ML-командой.

## Промежуточный результат парсера внутри ML

Парсер ML-команды возвращает структуру документа. Это пример промежуточного формата, который команда ещё должна согласовать:

```json
{
  "document_id": "uuid",
  "format": "docx",
  "blocks": [
    {"kind": "paragraph", "text": "Общая трудоёмкость: 144 часа", "source_ref":
      {"section": "Трудоёмкость", "locator": "block:12"}},
    {"kind": "table", "rows": [["Код", "Компетенция"], ["ОПК-1", "Текст"]],
     "source_ref": {"section": "Компетенции", "locator": "table:2"}}
  ],
  "warnings": []
}
```

У каждого блока есть источник. Формулы XLSX требуют отдельно оговорённых правил;
парсер не подменяет вычисление формулы предположением. Реальный парсер здесь ещё не написан.

## Передача результата ML бэкенду

```json
{
  "document_id": "uuid",
  "entities": [
    {"local_id": "discipline-1", "kind": "discipline", "attributes":
      {"name": "Программирование"}, "evidence": [{"locator": "block:4"}]}
  ],
  "observations": [
    {"entity_local_id": "discipline-1", "field": "hours", "value": 144,
     "evidence": [{"locator": "block:12"}], "confidence": 0.9}
  ],
  "relations": [],
  "warnings": []
}
```

local_id — временный ID внутри результата извлечения, не ID сущности в базе.
Этот пример не является телом существующего POST /versions: тот принимает полный
snapshot с UUID. Преобразование результата ML в снимок и сохранение observations
потребуют реализации на следующих этапах.
Сопоставление между документами — задача ML; бэкенд сохраняет предложенные результаты
и источники. Он проверяет структуру и принадлежность объектов программе/версии.
Неуверенное сопоставление не превращается автоматически в подтверждённый факт.

В первом этапе этот обмен существует как пример для обсуждения. Вызова Qwen,
контракта рабочего ML-пакета, проверки образовательных стандартов и агента пока нет.
Перед реализацией согласовать с ML типы сущностей, ошибки, обязательность источников
и формат результата сопоставления. Демонстрационная карточка не заменяет согласование.
